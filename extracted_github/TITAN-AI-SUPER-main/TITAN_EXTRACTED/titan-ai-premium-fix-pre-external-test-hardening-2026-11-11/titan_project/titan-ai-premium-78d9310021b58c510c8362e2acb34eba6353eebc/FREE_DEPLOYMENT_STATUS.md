# حالة النشر المجاني - تقرير صريح

تاريخ: 2026-11-07
**حالة النشر الفعلي:** لم يتم النشر على استضافة خارجية (لا يمكن تنفيذه تلقائياً من هذه البيئة بدون حساب/مصادقة المنصة)

## ما تم تجهيزه
- Dockerfile جاهز للنشر
- `render.yaml` للتهيئة السريعة (مع ملاحظات)
- تفعيل حماية/مصادقة افتراضياً للإنتاج (`TITAN_AUTH_REQUIRED=true`)
- CORS قابل للتقييد عبر `TITAN_ALLOWED_ORIGINS`
- فصل صارم: Spot Testnet / Futures Testnet / Live معطل تقنياً
- حفظ مفاتيح Testnet مشفر على الخادم
- نقطة معلومات نسخ احتياطي `/api/backup/info`
- جميع الميزات والمحركات محفوظة بدون حذف

## القيود المهمة (يجب معرفتها بوضوح)

### 1) التشغيل 24/7 على المجاني
**لا يمكن الادعاء بأن النظام يعمل 24/7 على الخطط المجانية.**
- Render Free: الخدمة قد تتوقف (spin down) بعد فترة خمول وتحتاج وقت للاستيقاظ
- Railway/Fly.io المجاني: رصيد/حدود قد تنفد، وقد لا يكون Always-On مضموناً
- **النتيجة:** التحليل والمراقبة المستمرة 24/7 **غير مضمونة** على المجاني

### 2) التخزين الدائم
- على المجاني، التخزين الدائم (Volume/Disk) قد يكون محدوداً أو غير متاح كما هو مطلوب
- بدون تخزين دائم: قد تُفقد قاعدة البيانات والإعدادات عند إعادة النشر/إعادة التشغيل

### 3) الرابط العام
- لا يمكنني إنشاء رابط HTTPS عام من هذه البيئة بدون النشر الفعلي على منصة خارجية
- النشر يتطلب: حساب على المنصة، ربط المستودع/الكود، وإعدادات النشر (بدون دفع)

## خطوات النشر المجاني (بدون دفع، تحتاج تنفيذك)
1. أنشئ حساب مجاني على Render.com (أو المنصة المختارة)
2. ارفع المشروع إلى GitHub (أو استخدم النشر المباشر إن توفر)
3. اربط المستودع واختر "Web Service"
4. اضبط: Build = `pip install -r backend/requirements.txt`
5. Start = `cd backend && uvicorn app.star_app:app --host 0.0.0.0 --port $PORT`
6. أضف متغيرات البيئة (خاصة `TITAN_AUTH_REQUIRED`, `TITAN_SECRET_KEY`, `PYTHONPATH`)
7. **Render Free لا يدعم Persistent Disk**؛ إعداد Render المجاني يستخدم SQLite مؤقتاً في `/tmp` للتجربة فقط. لا تعتمد عليه لحفظ البيانات أو بيانات Testnet. للاستمرارية استخدم خدمة مدفوعة مع Disk أو قاعدة بيانات دائمة مناسبة
8. انشر واحصل على رابط HTTPS

**تحذير:** تحقق أن الخطة مجانية بالكامل ولا تطلب بطاقة بنكية قبل المتابعة.

## ما لم يتم تفعيله
- التداول الآلي (يحتاج موافقتك الصريحة بعد إدخال مفاتيح Testnet واختبار الاتصال)
- Live (معطل تقنياً)

**الخلاصة:** المشروع مجهز للنشر المجاني، لكن النشر الفعلي والرابط العام و24/7 الحقيقي **غير مكتملين** من هذه البيئة ويعتمدون على قيود الاستضافة المجانية.


## تحديثات أمان وواجهة الهاتف (2026-11-08)
- وضع الإنتاج يُفعّل في إعداد Docker وRender، والمصادقة مطلوبة افتراضياً.
- CORS يرفض wildcard في الإنتاج؛ عند استضافة الواجهة على نطاق منفصل يجب ضبط `TITAN_ALLOWED_ORIGINS` على النطاقات الدقيقة مفصولة بفواصل. الطلبات من نفس النطاق لا تحتاج CORS.
- أضيف Service Worker وSVG icon للواجهة الأمامية. التخزين المؤقت يقتصر على غلاف التطبيق والملفات الثابتة؛ لا تُخزّن استجابات `/api/` أو بيانات الحساب. وظائف السوق والحساب تحتاج اتصالاً بالإنترنت.
- الواجهة الأمامية React/Vite تحتاج بناءً ونشراً منفصلين: `cd frontend && npm ci && npm run build` ثم نشر `frontend/dist` على استضافة HTTPS. ملف Render الحالي يجهز خدمة Backend فقط؛ لا يعني ذلك أن الواجهة الأمامية نُشرت.
- لا يوجد APK Android أصلي مولّد أو موقّع في المستودع حالياً. يمكن تثبيت الواجهة كـ PWA بعد نشرها عبر HTTPS ودعم المتصفح، لكن ذلك ليس APK مستقلاً.


### تنبيه Render Free (تم التحقق من الوثائق الرسمية 2026-11-08)
- خدمات Web المجانية لا تدعم الأقراص الدائمة، ونظام الملفات مؤقت؛ قد تضيع قاعدة SQLite والملفات عند إعادة التشغيل أو Spin-down أو إعادة النشر.
- لذلك تم تعديل `render.yaml` لإزالة إعداد Disk غير المدعوم واستخدام `/tmp/titan.db` المؤقت.
- هذا الإعداد للتجربة وDemo فقط، وليس لتشغيل تداول أو حفظ حسابات/مفاتيح.
- القرص الدائم يتطلب خدمة مدفوعة؛ لا يتم تفعيلها أو شراؤها دون موافقة المستخدم.

- Docker أصبح يجهز مجلد `/data` ويعلنه كـ Volume، ويستخدم `TITAN_DATA_DIR=/data` لتخزين مفاتيح Testnet المشفرة بجانب قاعدة البيانات عند ربط Volume دائم فعلياً. يجب على مستضيف Docker ربط `/data` بتخزين دائم؛ وجود `VOLUME` وحده لا يضمن بقاء البيانات على كل منصات الاستضافة.


### ربط الواجهة المستضافة منفصلاً بالـ Backend
- يدعم العميل الآن متغير البناء `VITE_API_BASE_URL` لتحديد أصل الخادم، مثال: `https://your-backend.example.com` (من دون مسار `/api` في النهاية).
- قبل بناء الواجهة: عيّن `VITE_API_BASE_URL` إلى رابط Backend الفعلي، ثم نفّذ `cd frontend && npm ci && npm run build` وانشر محتويات `frontend/dist` على استضافة HTTPS.
- في Backend اضبط `TITAN_ALLOWED_ORIGINS` على أصل الواجهة فقط، مثال: `https://your-frontend.example.com`؛ لا تستخدم `*` في الإنتاج.
- إذا كانت الواجهة والـ Backend على النطاق نفسه، اترك `VITE_API_BASE_URL` فارغاً واستخدم مسارات `/api` النسبية.
- قيمة `VITE_API_BASE_URL` تُضمّن وقت البناء؛ تغييرها بعد إنشاء ملفات `dist` لا يغيّر عنوان API داخل الملفات المنشورة، بل يلزم إعادة البناء.
- أصبح Blueprint في Render يطلب إدخال `TITAN_SECRET_KEY` و`TITAN_ALLOWED_EMAILS` صراحةً عبر `sync: false` بدلاً من ترك الخدمة تبدأ بإعدادات دخول غير مكتملة. أنشئ مفتاحاً عشوائياً قوياً بطول 32 حرفاً أو أكثر، وأدخل البريد المسموح به فقط؛ لا تضع هذه القيم في المستودع.
